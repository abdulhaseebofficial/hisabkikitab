## Browser-gate root causes and fixes

The global `AuthProvider` previously called `GET /api/auth/me` on every page load, including anonymous public pages. A 401 triggered the API client's `POST /api/auth/refresh`; the provider then made a redundant second refresh attempt. React Strict Mode doubled the initial development requests. Public pages now defer cookie-session restoration until a protected route needs it. Protected routes still restore through `/auth/me` and the API client's single refresh path. Explicit login and registration mark the session restored. A signed-in user opening `/` in a fresh tab now sees the public homepage until choosing “My finances”; an in-memory signed-in session remains available during client navigation.

The login page also requested `GET /api/auth/config`, a public endpoint that the old test catch-all incorrectly answered with 401. The local browser test now returns its documented public 200 response shape for exactly that path. Every other API route retains the signed-out 401 test response, and any unexpected request or response fails the representative-page network gate.

The blocked font request was the `fonts.googleapis.com/css2` stylesheet imported by `index.css`. The same Inter and Source Serif 4 font families are now bundled from Fontsource variable-font packages and served as first-party WOFF2 assets. Production CSS no longer requires Google Fonts. No test-time font stub or console-error suppression remains.

Unresolved SEO risks: no suitable bundled social share image. Production Search Console and live crawler behavior were not inspected because deployment and provider work are outside this task.
