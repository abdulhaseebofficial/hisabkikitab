## F10 recurring Shared Living bill-copy continuation — 5 October 2026

**F10 verdict: Mitigated locally; production-history preflight: Cannot confirm. Phase 2 remains NOT READY.** Migration `0021_shared_bill_occurrence.sql` adds `sl_bills.recurring_origin_id`, a same-space foreign key to the root bill, and a partial unique index on `(space_id, period_id, recurring_origin_id)` where the origin is present. This defines one generated occurrence as one recurring root bill in one target period. A copy made from a previous copy retains the root ID; two distinct bills with identical names, categories and amounts remain distinct. The index includes soft-deleted copies, so deletion cannot free an occurrence for a duplicate. A trigger prevents origin reassignment. New month copies retain a fresh request ID and version 1, preserving F11's request and stale-write rules.

Historical bills have no trustworthy source identity. Migration 0021 leaves their origin NULL and adds `recurrence_identity_known`: existing rows remain NULL, while newly inserted rows default to true. No old bill, share, payment, period, activity or amount is deleted, merged, reassigned or backfilled by name. Copying into a target period that contains any pre-cutover bill, or copying from a pre-cutover source period with same-name/category recurring candidates, now returns the stable 409 `shared.legacyBillReview`. These conservative stops avoid an ambiguous historical retry or propagation of obvious candidate duplicates. They can block a valid copy until the old bills are reviewed. There is no automatic historical reconciliation or override. The SQL preflight rejects exact non-NULL origin conflicts before creating the index. A diagnostic query groups old recurring rows by `(space_id,period_id,name,category_id)` to surface candidates for review, but those fields do not prove identity. A restored production-history copy was unavailable, so actual candidate conflicts, migration lock/runtime, and any manual reconciliation remain **Cannot confirm**. Rollback is a reviewed forward-only schema/application operation; dropping the new fields after new copies exist would discard lineage and is not automated.

The service removed the name/category deduplication query and inserts copies with `ON CONFLICT` against the partial unique index. A race or retry returns a successful empty result for an occurrence already copied, without exposing a PostgreSQL error. The existing space lock still serializes authorized operations, and the index is the independent database backstop. Source enumeration still uses the period-scoped bill query; no speculative source index was added. On the tiny disposable DB, its `EXPLAIN (ANALYZE, BUFFERS)` chose a sequential scan and sort over 41 rows (0.151 ms, 9 shared hits); an occurrence lookup also chose a sequential scan over 35 rows (0.030 ms, 1 shared hit).
